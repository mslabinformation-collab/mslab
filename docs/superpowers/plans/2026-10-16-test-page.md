# The Test Page ("Testimine") Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An admin page `/admin/testimine` where Maria and Dim walk the live site through a committed checklist, answer each check OK / Viga / Jäta vahele with a note, and see one shared result. A "Viga" reaches Dim on Telegram, and checks reopen when the code they describe changes.

**Architecture:**
- **The plan** is a committed JSON file (`app/src/data/testplan.json`), checked by a unit test for shape and house style.
- **The answers** are one `settings` row (`testplan_answers`), merged per check under a row lock, stamped with the server's clock.
- **The rules** live in one pure module (`src/domain/testplan.ts`): open/done/failed, the merge, the Telegram messages and the tester match. The server, the page and the tests share them.
- **The page** is a client component with a small outbox in `localStorage`, so a press on a flaky tablet is never lost.

**Tech Stack:** Next.js 16.3.8 App Router (pinned), Drizzle 0.45 + postgres.js, PGlite DB tests, vitest + happy-dom, Playwright e2e. Telegram goes through `sendTelegram` (`src/server/notify.ts`).

**Spec:** `docs/superpowers/specs/2026-10-16-test-page-design.md` (approved by Dim 16.10.2026). Read it first: the decisions D1–D10 and §3–§7 are binding.

## Global Constraints

- **Access.** Admin only: every route uses `withAdmin` (`src/server/auth.ts`), and the page is under `src/app/admin/(panel)/`. It is not in the admin's main menu. It is linked from the overview page (`src/app/admin/(panel)/page.tsx`) by a card.
- **Language.** All copy is Estonian (spec D2), with the house quotes „…“. The fixed texts are listed below under "Copy"; use them verbatim.
- **No migration, no new configured variable.** The answers are `settings` key `testplan_answers`. The build instant is inlined by `next.config.ts` as `TESTPLAN_BUILD_AT`. It is not a configured variable, and `.env.example` and `docs/deploy.md` §5 do not list it.
- **Answer shape.** `{ v: 1, answers: { [id]: { status: "ok" | "bad" | "skip", note: string, at: string, by: string, pinged?: string, notePinged?: true } } }`.
  - `at`, `pinged`: ISO instants, server clock.
  - `by`: the session's admin e-mail. It is never printed in logs and never sent to the browser. The page gets `byName` instead (below).
- **Limits.** A note holds at most 1 000 characters, counted with `Array.from` after trimming; a note of only white space is `""`. A request body is at most 128 KB.
- **Old Safari.** No regex lookbehind in any browser file. Add every new `"use client"` file and every file it imports to the import walk in `tests/unit/old-safari.test.ts`; the walk follows imports by itself, so check it covers them.
- **The public repo's guard.** No real e-mail address and no `@gmail.com` anywhere in tracked files, the plan JSON included (`tests/unit` already rejects `@gmail.com`). The test address in the plan is written "oma aadress, kuhu lisad enne @-märki +proov1".
- **Logs.** Ids, counts and statuses only: never a note, an e-mail address or a name.
- **No AI tool names client-facing.**
- **Vercel Hobby.** The route answers in well under a second, with `maxDuration` left at its default.

## Review Focus

1. **Maria and Dim save at the same moment.** Both answers survive, and neither erases the other: the merge happens under the row lock. Task 2 has a DB test with two concurrent saves.
2. **A press on a tablet with no connection.** The answer shows as "Salvestamata — proovin uuesti", survives a reload, and is sent when the connection is back. Task 3 has a DOM test of the outbox and an e-2e test with `context.setOffline`.
3. **"Viga" first, the note a second later.** The first message goes out ("(märkust veel pole)"), then exactly one more with the note, and nothing on later edits. A Viga after a `redo` is a new failure with its own messages. Task 1 has a unit table and Task 2 a DB test.
4. **The plan file changes under existing answers.** An answer to a removed id is kept but never counted or sent to the page. A new id is open. A `redo` answered before its instant is open, with the old answer shown under it. Task 1 has a unit table.
5. **A note of spaces, emoji or 5 000 characters.** Spaces become `""`. Emoji count as one character each. Anything over 1 000 is cut at 1 000 on the server, and the page's field stops at 1 000. Task 1 unit tests the server side; Task 3 has the DOM side.

```ts
export type Who = "maria" | "dim" | "koos";
export type Device = "telefon" | "tahvel" | "arvuti" | "any";
export type Mark = "redo" | "reworded" | "new";
export type TestArea = { id: string; name: string; note?: string; checks?: false }; // checks:false = a notes-only area ("Enne alustamist", "Koristamine")
export type TestItem = { id: string; area: string; who: Who; device: Device; title: string; href?: string; steps: string[]; expect: string[]; why: string; risk: "high" | "med" | "low"; writes: boolean; mark?: Mark; markedAt?: string };
export type TestPlan = { version: 1; marked: string; areas: TestArea[]; items: TestItem[] };
export type Status = "ok" | "bad" | "skip";
export type StoredAnswer = { status: Status; note: string; at: string; by: string; pinged?: string; notePinged?: true };
export type AnswersDoc = { v: 1; answers: Record<string, StoredAnswer> };
export type IncomingAnswer = { status: Status; note: string; clientAt?: string };
export type CheckState = { state: "open" | "done" | "failed"; answer: StoredAnswer | null; overtaken: StoredAnswer | null };
export type Ping = { id: string; kind: "bad" | "note" };

export const NOTE_MAX = 1000;
export function checkPlan(plan: unknown): string[];                       // problems, [] when fine (shape + house style, spec §3)
export function appliesAt(item: TestItem, plan: TestPlan, buildAt: string): string | null; // the instant a redo is judged by; null without a redo
export function checkState(item: TestItem, answer: StoredAnswer | undefined, plan: TestPlan, buildAt: string): CheckState;
export function cleanNote(raw: unknown): string;                         // trimmed, "" for white space, cut at NOTE_MAX code points
export function readAnswersDoc(value: unknown): AnswersDoc;              // a stored value of any shape → a valid doc (bad entries dropped)
export function mergeAnswers(stored: AnswersDoc, incoming: Record<string, IncomingAnswer>, plan: TestPlan, by: string, now: Date): { doc: AnswersDoc; changed: string[] };
export function pingsFor(before: AnswersDoc, after: AnswersDoc, changed: string[], plan: TestPlan, buildAt: string): Ping[];
export function markPinged(doc: AnswersDoc, pings: Ping[], now: Date): AnswersDoc;
export function testerOf(email: string, adminNames: string | undefined): Exclude<Who, "koos"> | null;
export function planCounts(plan: TestPlan, doc: AnswersDoc, buildAt: string, who: Exclude<Who, "koos"> | null): { total: number; done: number; open: number; bad: number; redo: number };
```

- Consumes: `adminFirstName(email, names)` (`src/server/auth.ts`). It is server-only, so `testerOf` re-implements the same `"<address>=<name>,…"` parse. It does not import it, because this module is also loaded by the page.

**Rules the bodies must follow** (they are not determined by the signatures):
- **`appliesAt`:** for `mark: "redo"`, use `markedAt`, else `plan.marked`. A `markedAt` of `"deploy"` reads as `buildAt`. Without a redo it returns `null`.
- **`checkState`:**
  - No answer → `open`.
  - A redo whose answer's `at` < `appliesAt` → `open`, with `overtaken` = that answer.
  - Otherwise `bad` → `failed`; `ok` or `skip` → `done`.
- **`mergeAnswers`:**
  - Ids not in `plan.items` are ignored.
  - Each incoming answer becomes `{ status, note: cleanNote(note), at: now.toISOString(), by }`.
  - The stored entry's `pinged` and `notePinged` are kept **only** while it stays the same failure: the stored status was `bad`, the new status is `bad`, and the stored answer is not overtaken by a redo.
  - Answers stored for ids outside the plan are kept untouched.
  - `changed` lists the ids written.
- **`pingsFor`:**
  - For each changed id whose new status is `bad`: if `pinged` is unset, emit `{kind: "bad"}`.
  - If `pinged` is set, `notePinged` is unset and the note is non-empty, emit `{kind: "note"}`.
  - A brand-new `bad` that already has a note emits only `{kind: "bad"}` (its message carries the note) and is marked `notePinged` too: no second message.
- **`testerOf`:** the first word of the admin's ADMIN_NAMES name, lower-case; `"maria"` or `"dim"`, else `null`.
- **`planCounts`:**
  - Only items in the plan count.
  - `who` narrows the count to items whose `who` is that tester or `"koos"`. `null` counts all.
  - `redo` = open items whose state carries an `overtaken`.

- **Route.**
  - `GET /api/admin/testplan` → `{ ok: true, plan, answers: Record<id, PageAnswer>, you: { name, tester } }`. On a database failure → `503 { ok: false, error: "unavailable", plan, answers: null, you }`.
  - `PUT /api/admin/testplan` with body `{ answers: Record<id, IncomingAnswer> }` → `{ ok: true, answers }` (merged, page form). Errors:
    - `400 { ok: false, error: "invalid" }` for a bad body;
    - `413 { ok: false, error: "tooLarge" }` over 128 KB;
    - `503 "unavailable"`.
  - All answers are `cache-control: no-store`. 401/403 come from `withAdmin`.

**Rules:**
- **`saveAnswers`:** one transaction.
  1. `insert into settings (key, value) values ('testplan_answers', '{"v":1,"answers":{}}') on conflict do nothing`;
  2. `select value from settings where key = 'testplan_answers' for update`;
  3. `readAnswersDoc`;
  4. `mergeAnswers`;
  5. `pingsFor`;
  6. `markPinged`;
  7. write the row back.

  It returns the pings; the route sends them with `after()`, once the transaction has committed. A failed Telegram send is logged as `[testplan] a Telegram message failed` with the check id, and never changes the answer.
- **Body validation** happens before the transaction. The body must be an object with `answers` as an object of `{ status ∈ Status, note: string }`. `clientAt` is ignored by the server (the outbox uses it in the browser only). More than 300 ids in one body → `invalid`.
- **`pingText`:** the "Copy" texts `tg.bad` and `tg.note`. The name is the answerer's first name from ADMIN_NAMES, or "admin". The note is the first 300 code points, or `tg.noNote`. The url is `<base>/admin/testimine#<id>`.
- **The log line of a save:** `[testplan] saved N answers, M messages`. Counts only.

  answer(id: string, status: Status, note: string): void;   // queue + save at once (a status press)

  flush(): Promise<void>;
  status(): "idle" | "saving" | "saved" | "retrying" | "offline";
  onChange(fn: () => void): () => void;
  stop(): void;
};
export function createOutbox(deps: { storage: Storage | null; put: (body: { answers: Record<string, IncomingAnswer> }) => Promise<Response>; now: () => number; setTimer: (fn: () => void, ms: number) => unknown; clearTimer: (t: unknown) => void; onAnswers: (a: Record<string, PageAnswer>) => void }): Outbox;
