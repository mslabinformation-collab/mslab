# Student reviews („Õpilaste tagasiside") Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A graduate can let her answer to „Kas soovitaksid seda koolitust ka teistele? Miks?" be shown on the site, under a name she chooses. Maria publishes or hides each one. Published ones show under their course and, if Maria picks them, on the home page. The student can take her permission back at any time. E-course graduates get the same feedback form once their course is „Lõpetatud". Maria can also add reviews she received elsewhere.

**Architecture:**
- **Migration 0014 (additive):**
  - `course_feedback` gains an e-course path: `access_id`, with `registration_id` made nullable and a check that exactly one of the two is set.
  - A new `reviews` table holds a frozen copy of the text and the name, a status and a featured flag.
- **Pure rules:** `src/domain/review.ts`.
- **Server:** `src/server/reviews.ts`. It covers the student's consent inside the feedback submit's transaction, the withdrawal, Maria's decisions, manual reviews and the public reads.
- **Public:** a server component `ReviewList` on the course page and on the home page, refreshed through `cache-targets.ts`.

**Tech Stack:** Next.js 16.3.8 (pinned), Drizzle 0.45 + postgres.js, vitest + PGlite, Playwright.

**Spec:** `docs/superpowers/specs/2026-10-18-reviews-design.md` (approved by Dim 18.10.2026). D1–D8 and §3–§6 are binding.

- **Logs** carry ids only: no names, no texts.

## Review Focus

1. **She withdraws a published, featured review.** It leaves the course page and the home page at once: the cache targets are called, and the row is gone. Tested in Task 3 (DB + unit) and Task 6 (e2e).
2. **A tick without a usable answer or name.** Covers a blank recommend text, a blank or whitespace name, and a name over 40. The submit is refused with a field error, and neither the feedback nor the review is stored. Task 2 DB test.
3. **An unpublished course.** Its reviews show nowhere, the home page included, and they come back when it is published again. Task 2 DB test.
4. **She deletes her account.** Her reviews go with it (cascade), and the public pages are refreshed. Task 3 DB test.
5. **Maria presses „Avalda" on a review the student has just withdrawn.** She gets the friendly text, with no 500 and no stale row. Task 4 test.

```ts
// schema.ts
// courseFeedback: registrationId becomes nullable; + accessId: integer("access_id").references(() => courseAccess.id, { onDelete: "cascade" });
//   uniqueIndex("course_feedback_access").on(t.accessId); check("course_feedback_one_target", sql`(registration_id is null) <> (access_id is null)`)
export const reviews = pgTable("reviews", {
  id, courseId: integer().notNull().references(() => courses.id, { onDelete: "cascade" }),
  feedbackId: integer().references(() => courseFeedback.id, { onDelete: "cascade" }), // unique; null for "manual"
  kind: text().$type<ReviewKind>().notNull(), text: text().notNull(), name: text().notNull(), locale: text().$type<"et" | "ru">().notNull(),
  writtenAt: timestamp tz notNull, status: text().$type<ReviewStatus>().notNull(), featured: boolean().notNull().default(false),
  decidedAt: timestamp tz, note: text(), createdAt, updatedAt });
// uniqueIndex("reviews_feedback").on(feedbackId); index("reviews_course_status").on(courseId, status, writtenAt.desc())
export type Review = typeof reviews.$inferSelect;

// domain/review.ts (pure)
export type ReviewKind = "student" | "manual";
export type ReviewStatus = "pending" | "published" | "hidden";
export const REVIEW_TEXT_MAX = FEEDBACK_TEXT_MAX; export const REVIEW_NAME_MAX = 40;
export const COURSE_REVIEWS_SHOWN = 6; export const COURSE_REVIEWS_MAX = 50; export const HOME_REVIEWS_MAX = 6;
export function shownNameFrom(fullName: string): string;            // "Kati Maria Kask" → "Kati K."; "Kati" → "Kati"; "  " → ""
export type ConsentCheck = { ok: true; name: string } | { ok: false; error: "consentText" | "consentName" };
export function checkConsent(recommend: string | undefined, name: unknown): ConsentCheck; // collapses whitespace, caps at REVIEW_NAME_MAX (longer → error)
export type ManualReviewInput = { courseId: number; name: string; text: string; writtenAt: string /* YYYY-MM-DD */; locale: "et" | "ru"; note: string };
export function checkManualReview(raw: unknown): { ok: true; value: ManualReviewInput } | { ok: false; fields: Record<string, string> };
export function reviewMonth(writtenAt: Date, locale: "et" | "ru"): string; // Tallinn time: "okt 2026" / "окт. 2026"
```

**Rules:**
- **The e-course target.** It is the client's access to that course. The form is open when `completed_at` is set and `revoked_at` is null. The access row is read FOR SHARE, the same way `own()` reads the registration.
- **Consent in the submit.** `consent` is checked first, with `checkConsent` against the answers' `recommend`. A failure writes nothing. On success, a review row (`kind: "student"`, `status: "pending"`, `writtenAt = now`, `locale` = the form's) is inserted in the submit's transaction, after the feedback row. A second submit is "sent" and writes no second review (`reviews_feedback` unique).
- **Ownership of `withdrawReview`.** The review's feedback must be hers, through its registration's `client_id` or its access's `client_id`. It deletes the row, whatever its status.
- **Maria's decisions.**
  - `decideReview` and `setFeatured` lock the row FOR UPDATE and answer `gone` when it does not exist.
  - `setFeatured(true)` requires `published`.
  - Hiding keeps `featured` (spec §5).
- **Manual reviews.** `saveManualReview` and `deleteManualReview` touch `kind = "manual"` rows only. An id of a student review answers `fields: { form: "notManual" }`. A new manual review is `published` (spec D4).
- **Maria's notice.** It gains the spec's line when `publishable`.
