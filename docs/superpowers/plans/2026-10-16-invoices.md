# Invoices ("Arved") Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every euro a student pays gets a numbered invoice. The PDF is in her account and in her mail. Maria can make, send, mark paid, undo and cancel invoices from a registration. A monthly CSV export serves her accountant.

**Architecture:**
- **Storage.** An additive migration 0011 adds `invoices`, plus `payments.invoice_id` for the unpaid invoice a Montonio payment pays. Each invoice row is a frozen copy of the seller, the buyer and the line.
- **Rules.** Pure rules live in `src/domain/invoice.ts`. The server is `src/server/invoices.ts`: issue, mark paid, undo, cancel, reads, CSV, settings.
- **Numbering.** Issues are numbered under the same lock pattern as the certificate: row locks, then `pg_advisory_xact_lock(hashtext('invoice-number'))`, then the setting. The series is per prefix and year.
- **Rendering.** The PDF is rendered on every download by `src/server/invoice-pdf.ts` with pdf-lib and Jost. It shares the MS LAB logo with the certificate through a new `src/server/pdf-logo.ts`.

**Tech Stack:** Next.js 16.3.8 App Router (pinned), Drizzle 0.45 + postgres.js, pdf-lib 1.17.1 + @pdf-lib/fontkit 1.1.1 (pinned), Resend 6.31 (attachments), vitest + PGlite, Playwright.

**Spec:** `docs/superpowers/specs/2026-10-16-invoices-design.md` (approved by Dim 16.10.2026). D1–D11 and §3–§9 are binding.

## Global Constraints

- **Staging.** mslab.ee is staging (Dim 14.10). Migration first, then the push: the live code must ignore 0011's additions, which it does because they are additive.
- **Never touch production.** Never `db:seed --target railway`. Never write on mslab.ee from an agent. Use local `next dev` against the local Docker database `mslab-pg` only.
- **Copy.** Estonian invoice PDF. Estonian admin. Estonian + Russian account and mail texts, held to the Russian-typography test (` ` escapes). Every new text is marked Draft in the task report for Dim's wording sheet unless the spec quotes it. The spec's quoted texts are verbatim: „Arve andmed", „Arveta maksed", „Koosta arve", „Maksmiseks", „Juba tasutud", „Tasumata", „Tasutud", „Tühistatud", „Saada õpilasele", „Saada ka aadressile", „Muuda saajat", „Märgi tasutuks", „Võta tasumine tagasi", „Tühista arve", „Laadi alla (PDF)", „Laadi alla (CSV)", „Näidisarve (PDF)", „Arve on lisatud.", the methods „Montonio", „Pangaülekanne", „Sularaha", „Kaardimakse kohapeal", and the VAT-off footer „Arve ei sisalda käibemaksu (müüja ei ole käibemaksukohustuslane)."
- **Money.** Amounts in cents, never floats. VAT from a gross amount: `vat = round(gross * rate / (100 + rate))`, `net = gross - vat`. Euro text `175,00 €`, with a comma and a non-breaking space before €.
- **Numbers.**
  - Format `{prefix}{year}-{nnn}`, with `nnn` padded to 3 digits (it grows past 999).
  - Uniqueness on `(prefix, year, seq)` and on `number`.
  - Tallinn year of issue.
  - A seq is never below that prefix-year's highest + 1 (the certificate's `seqToIssue` rule).
- **Locks, always in this order:**
  1. `lockForPayment(tx, registrationId)` (`src/db/queries/seats.ts`: the session, then the registration) when a registration is involved;
  2. the payment row or the invoice row `FOR UPDATE`;
  3. `pg_advisory_xact_lock(hashtext('invoice-number'))`;
  4. the `invoice` setting.

  The settings save takes the same advisory lock.
- **Access and caching.** A student reads only her own invoices, by her client id (`registrations.client_id` or `payments.client_id`). Admin routes use `withAdmin`; admin actions use `adminAction`. Every PDF and CSV answer is `private, no-store` with `x-content-type-options: nosniff`.
- **PDF stack.** pdf-lib loads lazily (`await import(...)`), as `certificatePdf` does. No new font. `next.config.ts` traces `./assets/fonts/**` into every function that renders an invoice PDF: account, admin, the payment routes, the cron, and the admin pages whose actions send.
- **Logs** carry ids, numbers and counts only: never names, e-mails or notes.
- **Old Safari.** No regex lookbehind and no `Object.hasOwn` in any browser file.
- **The test plan follows the code (standing rule).**
  - Each task that changes behaviour a check describes updates `app/src/data/testplan.json` in the same commit.
  - New behaviour gets new items with `"mark": "new", "markedAt": "deploy"`.
  - Changed behaviour gets `"mark": "redo", "markedAt": "deploy"`.
  - Only wording changes get `"reworded"`.
  - Ids never change.
  - `tests/unit/testplan-file.test.ts` must pass.

## Review Focus

1. **Two taps on „Märgi tasutuks", or Maria and the student's Montonio payment at the same moment.** The amount must be added once and the invoice paid once. Task 3 has a DB test with two concurrent marks, and Task 4 one with a mark against a settle.
2. **A transfer already typed into „Laekunud summa", then a „Juba tasutud" receipt.** „Laekunud summa" must not change. Task 3 DB test.
3. **„Maksa" with an unpaid 100% invoice on a 50% registration.** It must charge the invoice's 350 €, not `amountDue`'s 175 €. When paid, that invoice becomes paid, and no second invoice exists. Task 4 DB test.
4. **The seller card empty when a payment is paid.** The payment must be paid with no invoice and listed under „Arveta maksed". After the card is filled, its catch-up invoice carries the payment's paid time. Tasks 3 and 4.
5. **A prefix changed mid-year.** The new prefix starts at 001, and the old series keeps its numbers. No duplicate `number` may result. Task 1 unit test and Task 3 DB test.

  kind: text().$type<InvoiceKind>().notNull(), registrationId: integer().references(() => registrations.id, { onDelete: "set null" }),
  paymentId: integer().references(() => payments.id, { onDelete: "set null" }), courseId: …set null, clientId: …set null,
  status: text().$type<InvoiceStatus>().notNull().default("unpaid"), amountCents: integer().notNull(), vatRate: integer(),
  line: jsonb().$type<InvoiceLine>().notNull(), seller: jsonb().$type<InvoiceSeller>().notNull(), buyer: jsonb().$type<InvoiceBuyer>().notNull(),
  reference: text().notNull().default(""), issuedAt: timestamp tz notNull, dueAt: timestamp tz, paidAt: timestamp tz, paidMethod: text().$type<PaidMethod>(),
  paidAdds: boolean().notNull().default(false), sentAt: timestamp tz, sentNote: text().notNull().default(""), cancelledAt: timestamp tz, createdAt });
// unique: invoices_number(number), invoices_series(prefix, year, seq), invoices_payment(payment_id); index invoices_registration, invoices_client, invoices_issued(issued_at)
// checks: invoices_amount_positive (amount_cents > 0), invoices_seq_positive (seq > 0)
// payments.invoiceId: integer("invoice_id").references(() => invoices.id, { onDelete: "set null" }) — a plain column added with a FK
export type Invoice = typeof invoices.$inferSelect;

// domain/invoice.ts
export type InvoiceKind = "prepayment" | "full" | "balance" | "ecourse";
export type InvoiceStatus = "unpaid" | "paid" | "cancelled";
export type PaidMethod = "montonio" | "bank" | "cash" | "card";
export type InvoiceLine = { course: string; session: string; part: string };   // e.g. "Kulmumeistri baaskoolitus", "14.11.2026 Tallinn", "Ettemaks 50%"
export type InvoiceSeller = { company: string; registryCode: string; address: string; vatNumber: string; receiver: string; iban: string; bank: string };
export type InvoiceBuyer = { name: string; email: string; address: string; company: string; companyCode: string; companyAddress: string };
export type InvoiceSettings = { company: string; registryCode: string; address: string; vatNumber: string; vatOn: boolean; vatRate: number; prefix: string; nextYear: number; nextSeq: number; termDays: number; footer: string };
export const INVOICE_KEY = "invoice";
export const INVOICE_DEFAULTS: Omit<InvoiceSettings, "nextYear" | "nextSeq">;   // empty strings, prefix "MSL", vatOn false, vatRate 24, termDays 7
export const INVOICE_LIMITS = { company: 120, registryCode: 20, address: 200, vatNumber: 20, prefix: 10, footer: 300, termDays: 90, vatRate: 50, name: 120, buyerAddress: 200, note: 200 } as const;
export function readInvoiceSettings(value: unknown, now: Date): InvoiceSettings;
export function sellerReady(s: InvoiceSettings): boolean;                          // company, registry code and address all non-empty (D3)
export function formatInvoiceNumber(prefix: string, year: number, seq: number): string;   // "MSL2026-001"
export function invoiceSeq(s: { nextYear: number; nextSeq: number }, year: number, top: number): { seq: number; next: { nextYear: number; nextSeq: number } }; // reuse domain/certificate.ts seqToIssue
export function vatSplit(grossCents: number, rate: number | null): { net: number; vat: number; gross: number };
export function euro(cents: number): string;                                       // "175,00 €"
export type OpenAmount = { kind: InvoiceKind; cents: number; part: string };
export function openAmounts(r: { priceCents: number; paymentChoice: "full" | "half" }, invoiced: { kind: InvoiceKind; status: InvoiceStatus; amountCents: number }[]): OpenAmount[];
export function invoiceKindOfPayment(p: { kind: "prepayment" | "balance" | "ecourse" }, r: { paymentChoice: "full" | "half" } | null): InvoiceKind;
export function partText(kind: InvoiceKind): string;                               // "Ettemaks 50%" | "Kogu summa (100%)" | "Jääk 50%" | "E-koolitus"
export function invoiceFileName(number: string): string;                           // "MS-LAB-arve-MSL2026-001.pdf"
export function invoiceDownloadHeaders(number: string): Record<string, string>;
export function invoiceCsv(rows: Invoice[]): string;                               // §6.5: ";", UTF-8 BOM, CRLF
```

**Rules:**
- **`openAmounts`.** Cancelled invoices are ignored. "Covered" is the sum of unpaid and paid invoices.
  - Choice `half`: offer `prepayment` (half, rounded down to the cent) while no prepayment or full invoice exists. Offer `balance` (price − covered) when covered > 0 and < price.
  - Choice `full`: offer `full` while nothing is covered.
  - A `prepayment` and a `full` exclude each other.
- **`readInvoiceSettings`.** It mirrors `readCertificateSettings`. Bad or too-long fields fall back to the defaults. `nextYear`/`nextSeq` default to this Tallinn year and 1. `vatOn` is true only if `vatNumber` is non-empty.
- **`invoiceCsv`.** One row per invoice, in this column order: number, issue date (dd.mm.yyyy, Tallinn), due date, buyer name, buyer company, company code, description (`course — part`), net, VAT, total (comma decimals), state text, paid date, method text. A cancelled row has state „Tühistatud" and zero sums. Each field is quoted when it holds `;`, `"` or a newline.

```

**Rules:**
- **Issuing.** Every issue runs in one transaction, in the Global Constraints' lock order:
  1. the number lock;
  2. read the setting;
  3. `highestSeq` for that prefix and year (the year = Tallinn year of `now`);
  4. `invoiceSeq`;
  5. insert the frozen copies;
  6. advance the setting.
- **The seller copy** takes `prepaymentDraft(readSetting(prepayment))` for receiver, IBAN and bank.
- **Requests and receipts.**
  - A request (`mode: "request"`) has `dueAt` = issue + `termDays` days and `reference` = the registration's payment reference. Use the existing prepayment `referencePrefix` + the registration id, the same text the account shows today.
  - A receipt (`mode: "receipt"`) is born paid with the given `paidAt` and `method`, and `paidAdds: false`.
- **`markInvoicePaid`:**
  1. `lockForPayment`;
  2. the invoice `FOR UPDATE`;
  3. status must be `unpaid`;
  4. `addRegistrationPayment(tx, regId, amount, now)`;
  5. set paid, `paidAdds: true`.

  It returns `full: true` when `addRegistrationPayment` reports the session full; the registration then stays unconfirmed, as the online path does.
- **`undoInvoicePaid`:** only for a non-Montonio paid invoice. When `paidAdds`, take the amount back off `paidCents` with a decrement under the same locks, and recompute the status with `registrationStatusAfterPayment`. A confirmed place is taken back only if the payments rule allows it; follow `recordRegistrationPayment`'s semantics. Then set the invoice back to `unpaid`, with `paidAt`, `paidMethod` and `paidAdds` cleared.
- **`invoiceForPaidPayment`:**
  - If `payment.invoiceId` is set, call `markLinkedInvoicePaid` instead and return its invoice.
  - Otherwise, if `sellerReady`, issue an invoice: born paid, method `montonio`, `paidAt` = the payment's `paidAt`, `paymentId` set, kind from `invoiceKindOfPayment`, buyer from the payment's name and e-mail.
  - It never throws on a missing seller: it returns null.
- **`saveInvoiceSettings`.** Validate per `INVOICE_LIMITS`.
  - `vatOn` requires `vatNumber` → `"required"` on `vatNumber`.
  - The prefix must be letters or digits, 1–10 characters.
  - The next number is refused as `taken` at or below that prefix-year's highest.
  - `nextYear` must be this or next Tallinn year (as Seaded's certificate card).
  - Write under the number lock.
